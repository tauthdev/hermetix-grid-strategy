# hermetix-grid-strategy

**목표가 스캘핑 전략** — [hermetix-trading-core](https://github.com/tauthdev/hermetix-trading-core) 기반 넥스트증권 모의투자 봇.

원본은 Hana 프로젝트의 Bybit FeePlan(메이커 리베이트 숏 스캘핑)입니다. 모의투자에는 리베이트/PostOnly/공매도가 없으므로, 핵심 사이클을 **매수→매도 방향으로 뒤집어** 순수 시세차익 전략으로 이식했습니다.

## 전략 아이디어

"조금 싸게 사서, 조금 비싸게 판다"를 기계적으로 반복합니다. 목표가에 안 팔리면 목표를 단계적으로 낮춰(감쇠) 회전율을 지키고, 목표를 다 낮췄는데 수익권이면 시장가로 즉시 털어 다음 사이클로 넘어갑니다. 방향 예측 없이 횡보장의 잔파동을 수확하는 구조입니다.

## 동작 흐름

```
매 틱 (기본 30초, 미국 정규장 중에만)
│
├─ 보유 없음  (count ← max-decay-count 초기화)
│   ├─ 매수 미체결 있음
│   │   ├─ 가격이 chase-rate 이상 달아남 → 취소 (다음 틱에 재주문 = 추격)
│   │   └─ 아니면 대기
│   └─ 주문 없음 → 현재가 × (1 − buy-dip-rate) 지정가 매수 (DAY)
│
└─ 보유 중
    ├─ 매도 미체결 있음
    │   ├─ decay-minutes 경과 & count > 0 → 취소 + count−1 (다음 틱에 낮은 목표로 재주문)
    │   └─ 아니면 대기
    └─ 주문 없음
        ├─ count = 0 & 현재가 ≥ 평균단가 → 시장가 전량 청산  ← 원본의 "수익 나면 바로 시장가"
        └─ 그 외 → 평균단가 × (1 + target-rate × count) 지정가 매도 (GTC)
             (count = 0 이면 본전 지정가로 회복 대기)
```

### 예시 시나리오 (기본 설정, 100달러 종목)

1. 현재가 100 → 99.70 매수 지정가 → 체결
2. 103.00 매도 지정가 (평균단가 × 1.03, count=3)
3. 30분 미체결 → 취소, 102.00 재주문 (count=2) → 또 30분 → 101.00 (count=1) → 100.00 (count=0)
4. 그 사이 현재가가 99.85 → 100.10 반등 → count=0 이므로 **시장가 청산** (+0.4%)
5. 다시 1번부터

## 설정 파라미터

| 키 | 기본값 | 의미 | 조정 효과 |
|---|---|---|---|
| `grid.symbols` | AAPL | 감시 종목 목록 (쉼표 구분) | 종목별 독립 사이클. 예산은 종목 수로 분배 |
| `grid.buy-dip-rate` | 0.003 | 매수 지정가 깊이 (−0.3%) | 깊게 → 체결 드물지만 유리한 진입 |
| `grid.target-rate` | 0.01 | 목표 수익 단위 (1% × count) | 종목 변동성에 맞출 것 (아래 주의사항) |
| `grid.max-decay-count` | 3 | 감쇠 시작 count | 크게 → 초기 목표 높음 (3 이면 첫 목표 +3%) |
| `grid.decay-minutes` | 30 | 감쇠 판정 시간 | 짧게 → 목표가 빨리 내려와 회전율↑ 수익폭↓ |
| `grid.chase-rate` | 0.005 | 매수 추격 임계 (0.5%) | 작게 → 자주 추격 (주문 취소/재주문 빈번) |
| `grid.budget-ratio` | 0.5 | 진입 예산 비율 | — |
| `grid.poll-seconds` | 30 | 판정 주기 | 짧게 → 추격/감쇠 반응 빠름 |

## 주의사항

- **모의투자 학습용입니다.** 실제 투자 판단의 근거로 사용하지 마세요.
- **손절이 없습니다.** 이 전략은 하락 시 본전 지정가로 **무기한 대기**합니다 (원본 FeePlan 의 구조 유지). 하락 추세에 들어가면 자금이 계속 묶입니다. 손절이 필요하면 아래 커스터마이징을 참고하세요.
- **첫 목표가가 의외로 높습니다.** 기본 설정의 첫 매도 목표는 평균단가 +3% (target-rate 1% × count 3)입니다. 일중 변동 ±1% 안팎의 대형주라면 감쇠를 다 거친 후에야 체결되는 게 정상 동작입니다. 빠른 회전을 원하면 `target-rate: 0.003, max-decay-count: 2` 처럼 낮추세요.
- **평균단가는 계좌 기준입니다.** 매도 목표의 기준인 `avgEntryPrice` 는 이 전략의 진입가가 아니라 **계좌의 해당 종목 평균 매입 단가**입니다. 수동 매매나 다른 전략으로 같은 종목을 보유한 적 있으면 목표가가 의도와 달라집니다. **같은 심볼을 다른 전략과 동시에 돌리지 마세요.**
- **매수는 DAY, 매도는 GTC 입니다.** 장 마감 시 미체결 매수 주문은 소멸하고 다음 날 다시 걸립니다 (정상 동작). 매도는 체결까지 유지됩니다.
- **count 는 메모리에만 있습니다.** 재시작하면 count 가 초기값으로 돌아가 목표가가 다시 높아집니다 (감쇠를 처음부터 다시 진행).
- 주문 취소/재주문이 잦은 전략입니다. `poll-seconds` 를 너무 줄이면 API 레이트리밋에 걸릴 수 있습니다.

## 커스터마이징 포인트

`GridStrategy.kt` 에서:

- **손절 추가**: `decideSell()` 맨 앞에 `if (price < entryPrice × (1 − 손절률)) return listOf(Signal.Sell(시장가))` 한 블록을 넣으면 본전 대기 대신 손절합니다
- **본전 대기 완화**: count 소진 후 목표를 `entryPrice` 가 아니라 `entryPrice × 0.999` (수수료 감안 약간 아래)로 두면 회복 직전에 탈출합니다
- **감쇠 곡선 변경**: 목표 계산부 `targetRate × count` 를 `targetRate × count²` 등으로 바꾸면 감쇠 폭이 비선형이 됩니다
- **매수 조건 강화**: `decideBuy()` 에 RSI/이동평균 같은 필터를 추가하면 "아무 때나 사는" 리스크가 줄어듭니다 (`context.candles()` 사용 — `spec.candleLimit` 을 늘릴 것)
- **다중 종목**: `grid.symbols: AAPL,TSLA` 처럼 나열하면 종목별 독립 사이클로 동시 운용됩니다 (예산은 자동 분배)
